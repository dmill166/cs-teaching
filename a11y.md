# Accessibility Standard

> Every Dakota Learns lecture ships **accessible by default** — this is a build-time habit, not a post-hoc audit. Target: **WCAG 2.1 AA** + **Universal Design for Learning (UDL)**. Companion to [`STYLE.md`](STYLE.md) and the [Module Standard](MODULE_STANDARD.md). Grounded in the 2026-07-02 audit of the CS1 exemplar lectures.

## Contrast — check in BOTH light and dark (a real palette toggle ships)

- Body and title text ≥ **4.5:1**; large text (≥24px, or ≥19px bold) and meaningful UI ≥ **3:1**.
- Every meaning-carrying UI element — icons, borders, focus rings — must clear **3:1 against its own background**, not just the page.
- A color that passes one scheme can fail the other; validate both. The house accents that clear 3:1 in both are **green `#388e3c`** (self-checks) and **slate `#455a64`** (FAQ).
- Recolors live in **`dakotalearns/docs/stylesheets/extra.css` only** — never edit the generated `site/` CSS.

## Text alternative for ALL non-text content (WCAG 1.1.1)

- **Every diagram carries a description.** Mermaid diagrams get **`accTitle:`** (a caption line) **and** `accDescr:` (a full-sentence description naming every node and the direction of every arrow) as the first indented lines after the diagram-type line. `accDescr` is mandatory — `accTitle` alone doesn't convey the figure.
- Every `<img>` has meaningful `alt`, or `alt=""` if provably decorative.
- No meaning in color or position alone — a decision branch names the condition and both outcomes in its `accDescr`.
- Emoji stays decorative — never the sole carrier of meaning; wrap purely decorative glyphs in `<span aria-hidden="true">…</span>` when convenient.

## Differentiate by MEANING, on three channels (1.3.1 + 1.4.1 + UDL)

Encode a block's *purpose* in color **+** icon **+** type-word (never color alone). A given visual affordance is never reused for two different content roles.

| Role | Type | Color | Reads as |
|---|---|---|---|
| A question the **learner** answers (Check yourself) | `??? question` | green `#388e3c` | "answer this yourself" — go / self-test |
| A common question **we** answer (FAQ) | `??? faq` | slate `#455a64` | "here's a common answer" — calm reference |
| Instructor-only outcome mapping | `??? note "For instructors …"` | default | collapsed by default; keeps jargon off the student path |
| Non-collapsible asides | `!!! tip / note / warning / example` | per type | — |

## Structure & readability

- Exactly one `h1`; headings descend by one level, never skip (h2→h4 is a defect).
- Real semantic elements — native `<details>/<summary>`, real tables, real footnotes. No divs faking structure.
- Prose blocks over ~90–100 words get chunked (paragraph split, short list, or a small table/callout). **Chunk, don't dumb down** — keep the plain-language reading level (~grade 7), don't flatten the voice.
- Link text is self-describing out of context; identical destinations get identical link text; name the destination when it matters ("the official Python type docs", not "more types").

## Emoji — formal lecture = light touch

- Section-marker, sign-off, or running-analogy anchor only; **never** in headings, objectives, or key-term tables; never load-bearing. Target ~3–4 per lecture. Don't add more to seem friendlier.

## Keyboard & focus (2.1.1 / 2.4.7)

- Every interactive element is keyboard-reachable and toggles with Enter/Space, with a visible focus ring (≥3:1) on keyboard focus.
- Trust native semantics — do **not** add redundant ARIA (e.g., `aria-expanded` on a native `<details>`).

## Enforce it (CI gate — rides with the publish-lock gate)

When the publish-lock CI gate lands, add these checks so accessibility can't silently regress:

- Fail the build if any ` ```mermaid ` block lacks `accDescr`.
- Fail the build if any `<img>` lacks an `alt` attribute.
- Lint: FAQ sections use `??? faq`, self-checks use `??? question`.
